# 论文覆盖与验收

适用于论文解读、论文 PPT 和既有成品验收，不给普通短汇报增加无关流程。

## 内容与来源

先核对实际输入清单；数量冲突以文件和用户确认为准，不补造论文。每篇保留题名、版本及来源入口。需要“完整解读”时，用原文章节、关键公式、图表和附录建立覆盖清单，注明在解读笔记或幻灯片中的位置与省略理由。页数和字数不能证明无信息遗漏。

重要图、数值、公式应能定位到原文页码或图表编号；推导分清原文公式与教学简化，解释符号、单位、定义域及近似。论文截图允许保留为图片，自写独立公式应使用原生数学对象，不把 `x_t` 等普通字符串冒充原生公式。

实验结论保留任务、基线、样本量、指标方向与例外。消融支持相关比较，不自动等于因果证明；平均更优不等于每项更优。预测损失不保证物理正确；控制方法的名称不替代稳定性、无偏差或约束可行性的成立条件。训练时辅助监督和部署时输入必须分别说明。

## 制作中的具体陷阱

PowerPoint COM 的 RGB 整数使用 `r + 256*g + 65536*b`，不是直接将 HTML 十六进制色号转成整数。例如 `#F7EDE6` 应转换为 `247 + 256*237 + 65536*230`。优先使用有命名的转换函数，并从渲染结果复核实际颜色；代码注释中的色号不是视觉证据。

批量生成不能固定每篇页数、章节数或最小字号来凑一致。先满足原文的不同结构与听众需求。正文及灰色引入采用模板可读字号；长内容重组而非不断缩小。公式截图检查上下标和裁切，图注也要保留足够空间。

若使用 COM，区分自己打开的副本和用户已打开的文稿，不保存用户原稿，不在共享 PowerPoint 实例上无条件调用 `Quit()`。检查脚本尽量只读；修订输出使用独立文件名。

## 验收证据与交付表述

分别记录三层结果：

1. 结构：文件可打开、实际页数、逐页备注是否有实质内容、图表来源和数学对象类型。备注 XML 文件存在不代表备注完整。
2. 视觉：渲染全部页面并逐页查看，重点页再看原尺寸；核对可读性、遮挡、裁切、配色、边界和页脚。字符数/框尺寸启发式检查只用于筛选，不能替代渲染或真实文本边界检查。旧预览可能与当前 PPT 不一致，应记录其对应关系或重新导出。
3. 学术：回查关键主张、公式条件、结果表及负面结果。没有完成逐章覆盖核对时，不声称“原文信息全部保留”。

交付明确已做和未做的核验。抽样检查称为抽样，预计时长称为预计；未试讲不声称已验收时长。修正 skill 不自动意味着旧 PPT 已重新制作或通过新规则，已有缺陷单独列出并说明是否修复。
